# Astro site — pitfalls verified in this repo

Dated: Astro 7.4.2, pnpm 12, Oct 2026. Original template: `stacks/astro/skills/astro-static-site` in global-context (adapted copy).

## Markup

- **A line break between inline elements disappears** (`compressHTML: 'jsx'`). `<span class="n">02</span>Flow` rendered "02Flow"; the badge legend glued "Steam" to "LIVE". Use `{" "}` where words form a sentence. Check: build, then grep `dist/` for text glued to `<span|b|a|code>`.
- An HTML comment `<!-- -->` ships to the page; in templates use `{/* */}`.

## Mobile layout

- **A grid item with `min-width: auto` widens the page.** The calculator (`.calc-grid`) with fixed columns made the page 19 px too wide at 390 px. Use `minmax(0,1fr)` in `.grid2`/`.calc-grid`.
- 390 px on every page is checked by `pnpm test:e2e` (`e2e/pages.spec.ts`): `document.documentElement.scrollWidth <= clientWidth` **and** no `overflow-x: auto|scroll` box wider than itself — the play sheet's panes scroll on their own, so a too-wide child there never widens the page (a 600 px `min-width` passed the page-level check, verified 2026-10-17). The nav is excluded (it scrolls sideways on purpose). To find a culprit, list text nodes whose `Range.getBoundingClientRect().right` passes the container.

- **The nav scrolls sideways on phones, so nothing absolute may live in the scroller.** `overflow-x:auto` also clips Y: the language dropdown was cut off. `Base.astro` splits the bar into `.links` (scrolls) and `.nav-end` (language `<details>` + theme icon, `flex:none`). The event pages' "All events" link was cut off there at 390 px, so since 2026-10-17 it lives at the top of the page content (`src/components/BackLink.astro`), not in the nav.

## Content from outside `src/`

- Event docs live in `events/<Dir>/` (source of truth). `src/content.config.ts` uses `glob({ base: './events', pattern: ['*/*_GUIDE.md', '!_*/**'], generateId })` — the loader accepts a folder outside `src/`, and the `!_*/**` negation skips `events/_template`. The guide's frontmatter is the event card (zod schema); `src/lib/events.ts` builds the registry from it (plus `banner` and `hasPage` via `import.meta.glob`), so a new folder needs no code.
- **Astro 7 uses Sätteri as its markdown processor.** `markdown.rehypePlugins`/`remarkPlugins` fail the build asking for `@astrojs/markdown-remark` (matters if markdown pages come back; the site renders none since 2026-10-17).
- Event art comes in through `import.meta.glob('…/events/SS14_Tartarus/art/*.webp', { eager: true })` → `artSet()` (`src/lib/images.ts`) in `src/sheets/ss14/PlaySheet.astro`; the glob must be a static string. `artSet(id, size)` returns `null` synchronously for missing art (so `A(id) ? <Art …/> : placeholder` works) and otherwise a memoized promise that `<Art>` awaits — only the sizes actually drawn get generated (eager generation of every size tripled `dist/`).
- Page data: `import data from '…/tartarus_data.json'` in the frontmatter and `<script type="application/json" set:html={JSON.stringify(data).replace(/</g,'\\u003c')}>` — the escape keeps `</script>` inside the JSON from closing the tag. The SS14 sheet sends the engine's pairs and per-card values **packed** by the sorted ids (`src/sheets/ss14/pack.ts`, packed in the page, unpacked in `play.ts`): 4 start cards × 465 pairs spelled out were 39% of the page (45 → 38 KB gzipped, 2026-10-18). Tests read numbers from `engine_results.json`, never from the packed copy.

## GitHub Pages

- Internal links always go through `url()` from `src/lib/events.ts` (uses `import.meta.env.BASE_URL`). Check: `BASE_PATH=/repo/ SITE=https://x.github.io pnpm build`, then grep for `href="/` without the prefix.
- In the workflow, `github.event.repository` **does not exist on `schedule` events**: `BASE_PATH` comes from `${GITHUB_REPOSITORY#*/}`.
- A push made with `GITHUB_TOKEN` doesn't trigger another workflow: data refresh, dependency update and deploy live in the same file (`.github/workflows/deploy.yml`, jobs `update-data` → `update-deps` (Mondays) + `lint` → `build` → `deploy`). `update-deps` commits only `pnpm-lock.yaml` and fails on any other change (e.g. pnpm writing a release-age exclusion).
- **Node in CI is an exact version, in both jobs** (`setup-node` in `lint`, `withastro/action`'s `node-version` in `build`). A bare `24` takes the runner's cached 24.x: on 2026-10-23 the jobs ran 24.21.0, three days after the 24.22.1 security release (log line `Found in cache @ /opt/hostedtoolcache/node/<version>`). `withastro/action` has no `check-latest`, so the exact version is the only fix. Bump both on a Node security release, with `engines.node`.
- Pushing files under `.github/workflows/` over **HTTPS with the gh OAuth token** needs the `workflow` scope (`gh auth refresh -s workflow`). This repo's remote is **SSH**, which isn't restricted.

## Delivery on GitHub Pages (measured 2026-10-17)

- **Pages sets the headers, not us:** every file gets `cache-control: max-age=600`, `content-encoding: gzip` (no brotli), no way to add headers. Hashed `/_astro/*` files are revalidated every 10 min like everything else. Workarounds in the build: CSS inlined into each page (`build.inlineStylesheets: 'always'`), and `public/sw.js` (cache-first for `/_astro/`, network-first with a 3 s timeout for pages; registered only in `import.meta.env.PROD`, scope = base). Change the SW strategy → bump `VERSION` in it.
- **Network-first in the SW is not enough by itself** (found 2026-10-17, players on stale pages): `fetch(req)` in the worker goes through the browser's HTTP cache, so a plain navigation got the HTML Pages had sent with `max-age=600` — up to 10 min stale after every deploy. `fetch(req, { cache: 'no-cache' })` revalidates (a 304 when unchanged). A `reload()` is already `no-cache` and hides the bug: `e2e/sw.spec.ts` navigates away and back, and fails without the fix.
- **Open tabs never refresh on their own:** every page carries `<meta name="tli-build">` (git HEAD, `src/lib/build.ts`); `src/lib/update-check.ts` fetches the live page (`no-cache`) 1.5 s after load and when the tab becomes visible again (at most once a minute) and shows the Reload toast when the commit differs. A docs-only commit also changes HEAD, so it shows the toast too (harmless reload). Its Reload first puts a fresh copy (`fetch(url, { cache: 'reload' })`) into every `tli-pages-*` cache, then reloads: on a slow network the SW answers from that cache after 3 s, which would be the old page (`e2e/update.spec.ts` seeds an old copy and checks the new one is there).
- **robots.txt is useless on a project site** (crawlers only read `https://<user>.github.io/robots.txt`). The sitemap (`src/pages/sitemap.xml.ts`) has to be submitted in Search Console.
- `404.astro` → `dist/404.html`: Pages serves it for any missing path under the project; links inside must use `url()`.
- Baseline → after this setup, Lighthouse mobile on `pnpm preview`: home perf 89 → 100 (FCP 3.0 → 1.1 s; Google Fonts CSS was 2.4 s render-blocking), `/ss14/` perf 90 → 99, a11y 90 → 100, CLS 0.195 → 0.

## Fonts

- **Astro 7 `fonts` config + `<Font cssVariable preload>`** downloads at build time and self-hosts under `/_astro/fonts/`. It defaults to **normal + italic** for every weight: set `styles: ['normal']` (the site has no italics; every `<em>`/`<i>` is `font-style:normal`). List only the subsets a language needs (Barlow has no Cyrillic; IBM Plex Mono does).
- **Google's metadata API no longer lists "Big Shoulders Stencil Display"** (the old css2 URL still serves it; the API offers the successor "Big Shoulders Stencil", opsz axis, different look). The legacy Latin file is in `src/assets/fonts/` through `fontProviders.local()` — one variable file, its weight axis cut to the **400–700 the site uses** (measured 2026-10-18 on every page, cards open: 400, 600, 700; fontTools `varLib.instancer`, 36 → 25 KB). A heading asking for 800+ would render at 700: widen the cut first (the original is on fonts.gstatic.com v30). Astro's fallback `size-adjust` follows the axis default (54% at 100, now 67% at 400). Since 2026-10-18 (Polish) it is two files split by `unicodeRange` (Latin + latin-ext, same v30 source and cut); `<Font preload>` would preload both and its `subset` filter can't tell local variants apart, so `Base.astro` preloads only the first via `fontData['--font-display'][0]`. Barlow and Plex Mono just list `latin-ext` in `subsets`.
- **`display: 'optional'` means CI may draw with its own fallback font** (2026-10-18): the SS14 top bar fit French ("Tous les événements" 201 px + "Réinitialiser" 143 px of 366) locally, but the Linux runner's fallback made `/ss14/fr/` 401 px wide at 390 and failed v1.14.0 and v1.15.0's deploys while every local test passed. Blocking the fonts locally doesn't reproduce it (the local fallback differs too). Layouts wrap instead of relying on fitting, and `e2e/ss14.spec.ts` checks the Reset bar at **320 px** in every language.
- **Metric-matched fallbacks don't stop CLS:** same average width, different line breaks; the late Barlow swap reflowed the play sheet (CLS 0.2). Body + mono use `display: 'optional'` with the critical weights preloaded (400 + 700 Latin); only the heading face keeps `swap`.

## Images

- `<Art img=… />` (`src/components/Art.astro`) always emits `srcset` (1×/2× of the drawn box, `fixed()`) or width-based `srcset` + `sizes` (`fluid()`), intrinsic `width`/`height` and `loading="lazy"`; `eager` adds `fetchpriority="high"` (LCP image only — the home banner). An `<img>` without width/height (the inline `.inl` icons) caused layout shift.
- `fluid()` passes `width` = largest entry so the plain `src` is a srcset file, not a full-size copy.

## Tooling

- **Lint and format** (Oct 2026: ESLint 10.13, typescript-eslint 8.72, eslint-plugin-astro 3.2, @eslint/css 2.0, Prettier 3.9 + prettier-plugin-astro 1.1). Every ESLint block is scoped by `files` (a rule set without it also runs on CSS and crashes). `eslint-plugin-jsx-a11y` doesn't accept ESLint 10; the Astro plugin's `flat/jsx-a11y-recommended` works with `eslint-plugin-jsx-a11y-x`. In CSS, `allowUnknownVariables` (tokens live in `src/styles/theme.css`, fonts come from Astro's `<Font cssVariable>`) and `font-family-fallbacks` off (Astro builds the var from `fallbacks`, which ends in a generic family).
- **Formatting must not change the page:** `astroCompressHTML` defaults to `'jsx'`, same as Astro 7. The first full format (2026-10-17) was checked against the previous build: identical markup on every page, `/_astro/` unchanged, only whitespace inside `<script is:inline>`/`<style>`. Repeat that comparison after changing the Prettier config.
- **Pre-commit:** `.husky/pre-commit` runs `lint-staged --hide-all --concurrent false` (hide untracked files too, so `astro check` sees only what is committed; one glob at a time, so Prettier never rewrites a file ESLint is reading).

- **Browser tests** (`pnpm test:e2e` = `astro build && playwright test`; @playwright/test 1.64, Oct 2026). `channel: 'chrome'` uses the installed Google Chrome (the GitHub runner has one too), so no Playwright browser download. The `webServer` is `astro preview --port 4329 --ignore-lock`: with `--ignore-lock` Astro 7's preview runs in the **foreground** (Playwright can stop it) and leaves any preview the owner has open alone. Run by lint-staged (last, only for site paths) and by the CI `lint` job. Whole suite ~8 s with the build.
- **On touch the SS14 card opens as a modal `<dialog>` (`#popdlg`, since 2026-10-18)**: the tooltip covered a phone screen with no way to close or scroll it, and a tap beside it hit the row underneath (`pointer-events: none`). `play.ts` notes the pointer type on `pointerdown`: touch/pen → `showModal()` with a close button, Esc and a backdrop tap; mouse and keyboard keep the tooltip. A tap that takes the start pick re-sorts the list and **moving a node drops its focus**, so the dialog can't restore focus itself: `close` refocuses the opener, or its chip in Holding when its row left the list. Tested with `test.use({ hasTouch: true })` + `tap()` (real `pointerType: 'touch'`), plus axe on the open dialog.
- **Every `:hover` style lives under `@media (hover: hover) and (pointer: fine)`** (2026-10-18): on touch the last tapped element stays `:hover` until the next tap, so a row stayed lit; `:focus-visible` stays outside the query. `e2e/ss14.spec.ts` checks a tapped row keeps its calm colour (and that a mouse hover still lights it). New hover rules go inside that query. The generic list of desktop→touch traps is the global `web-touch-mobile` skill's; copy what applies here.
- **The SS14 tooltip (`#pop`, mouse and keyboard) has `pointer-events: none`, so it never scrolls**: what passes the screen is lost. `e2e/ss14.spec.ts` opens every instrument card at 360×740 in every language and holding one instrument, and fails on `scrollHeight > clientHeight` (Oct 2026: Russian and the "with what you hold" block overflowed where English fit). With **two** held it still overflows up to 27 px in Russian (run already decided; owner's call). `openCard` scrolls with `behavior: 'instant'`: the page's smooth scroll closed the card mid-test (8 of 20 runs). Since 2026-10-23 `showPop` measures instead of guessing: a card the screen would cut (`scrollHeight > clientHeight`) is not shown on hover or focus, and a click or Enter opens it as the dialog. The screen decides, not the text size: until then any A+ sent every card to the dialog, though at 125% on 1440×900 30 of 31 cards fit (holding one), and at 200% on 1366×768 24 of 31.
- **Accessibility gate: `e2e/a11y.spec.ts`** (@axe-core/playwright 4.14, Oct 2026) runs axe with the WCAG 2.x A/AA tags on every page in both themes (`page.emulateMedia({ colorScheme })`, which is what the theme follows until the reader picks one). axe skips hidden content, so `/ss14/` is checked again with every `<details>` open and with one card of each kind in `#pop`. The "new version" notice too, forced visible: its Reload was white on the dark theme's accent (2.8:1) until 2026-10-18; it now uses `--surface`. Before it, a link at 4.33:1 shipped in v1.6.0 and only Lighthouse saw it. axe does not check WCAG 2.2.2 (moving content), so the same spec asserts every CSS animation ends within 5 s (`document.getAnimations()`; the footer heart and the home sheen looped forever until 2026-10-18). Since v1.9.1 the heart beats endlessly again as its own pause toggle (`#heart`, `aria-pressed`, state in `localStorage` `tt-heart`, reduced motion starts paused): the 5 s check skips motion inside `button[aria-pressed]`, and two tests check the toggle; focus-ring contrast is unchecked (computed ≥ 4.95:1 for `--accent` on every surface, Oct 2026).
- **Translation offer (`src/lib/lang-offer.ts`, 2026-10-19):** a page with translations offers the one `navigator.languages` asks for, in a fixed box worded in that language — never a redirect (the client is English; crawlers). Answered once: "Don't show again" (`localStorage` `tli-lang` = `never`), a language followed or picked in the switcher (`tli-lang` = code), × or Esc for the tab (`sessionStorage`). Traditional Chinese tags skip our Simplified page. **The tests run in en-US, so every translated page would offer English over what they click: `playwright.config.ts` starts every spec with `tli-lang=never`**; `e2e/lang-offer.spec.ts` clears it (`test.use({ storageState: { cookies: [], origins: [] } })`) and sets `locale` per case.
- **`<details>` saves its state on `toggle`, which fires a task after the click**: a test that reloads right after `click()` sees the old state. Poll the storage first (`expect.poll`).
- **"Last simulation" comes from git** (`src/sheets/ss14/sim-time.ts`: the commit time of `engine_results.json`). The CI build job checks out with `fetch-depth: 0`; in a shallow clone `git log -- <file>` returns the one grafted commit's time for every file, so the module falls back to the export's UTC date (also when the export is uncommitted).
- `astro build` doesn't type-check; the gate is `pnpm check`. **`astro check` rejects TypeScript 7** ("install TypeScript 6") → `typescript@6`. The TS 7 + TS 6 alias (`"typescript": "npm:@typescript/typescript6@…"`) passes `astro check` (measured 2026-10-23), but `tsc` 7 skips `.astro` and no gate here runs `tsc`, so the alias would gain nothing: stay on plain TS 6. An endpoint using `node:fs` needs `@types/node`.
- **`astro dev` and `astro preview` run in the background in Astro 7** and return the prompt; stop with `pnpm astro preview stop` / `pnpm astro dev stop` (`status`, `logs`). Before testing a port, `ss -ltn` to see who is listening.
- Playwright (MCP) blocks `file://`: always test through `pnpm preview`.
- `astro preview` reads `astro.config.mjs` at start: to preview the Pages build, start it with the same env (`BASE_PATH=/tli-events/ SITE=https://johnsonmauro.github.io pnpm preview`), or assets 404 under the base.
- Lighthouse without installing: `CHROME_PATH=/usr/bin/google-chrome-stable pnpm dlx lighthouse@<version> <url> --chrome-flags="--headless=new" --form-factor=mobile --output=json` (reports to the scratchpad).
